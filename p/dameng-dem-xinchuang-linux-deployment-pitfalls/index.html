    DEM 管理端通过 dmagent 的 HTTP API（默认 6363 端口）采集被监控实例的指标数据，dmagent 再通过本地连接采集 DM8 实例信息

    通过在 DEM 中配置监控资源，便可以生成 metrics 数据，供 Prometheus 使用

    踩坑记录

    首先是信创Linux的架构，这次客户所用的机器是麒麟。官方文档提到DEM 和 dmagent 所在机器需要配置 JAVA 环境，JAVA 版本必须为 JAVA 1.8因此需要提前准备aarch64的Java JDK

    其次是资源紧张引出的新问题。官方文档有提到需要创建一个 DM 数据库作为 DEM 后台数据库，同时SYSDBA（或管理员用户）执行 SQL 脚本 dem_init.sql 而本次部署资源紧张，选择复用被监控节点其中一个实例作为DEM后台数据库。当然不能将业务数据库的SYSDBA直接配置过去，需要新建一个用户，给予DBA权限。

    接着是监控所需的用户，实测按照官方给的最小连接权限是不够的。还需要授予查询系统动态视图的权限。

    CREATE USER "TEST" IDENTIFIED BY "*******" LIMIT SESSION_PER_USER 50, CONNECT_IDLE_TIME 10;
GRANT "PUBLIC" TO "TEST";
GRANT SELECT TABLE, SELECT VIEW, SELECT SEQUENCE TO "TEST";

-- 授予查询系统动态视图的权限
GRANT VTI TO TEST;
    权限项说明
    PUBLIC角色对当前模式下对象的数据操作权限，不包含任何用户业务表的访问权限
    VTI角色V$动态性能视图，不包含任何用户业务表的访问权限
    SELECT TABLE可查询已被显式授权的表，但监控账号未获得任何业务表的GRANT，因此此权限对业务表无效
    SELECT VIEW可查询已被显式授权的视图，同上，对业务视图无效
    SELECT SEQUENCE可查询序列值，与业务数据无关
    session_per_user=50限制最大并发连接数，防止资源滥用
    connect_idle_time=10空闲10分钟自动断开，降低安全风险

    最后是意料之外的坑，但其实应该最早就确认下。在其中一台DEM具无法添加监控实例，提示【无效的主机，或主机上未启动数据库代理的情况】。经排查是这几台机器的时间偏差太多（接近二十分钟了也不知道是怎么埋下的坑），同步时间后正常添加监控。
