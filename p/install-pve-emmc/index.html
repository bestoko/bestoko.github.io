如何在eMMC上安装PVE与优化配置

Unable to get device for partition 1 on device /dev/mmcblk0

Dec 14, 2025

现象

今天在尝试给之前买的N150小主机虚拟化折腾下随身软路由+轻NAS时，本着不浪费M.2硬盘位的原则，想把PVE(9.1)装在自带的64G eMMC上一直报错。一开始是怀疑之前装fnos测试时的分区没清干净，到PE下格式化了两次仍然如此。

Installation failed!

Unable to get device for partition 1 on device /dev/mmcblk0

原因

检索后发现论坛上早有人提过，而官方的回复看起来则是不希望用户安装在eMMC上，因为会每天写入很多log，而eMMC之类在如此频繁写入下操作寿命堪忧。

无法获取设备 /dev/mmcblk0 上分区 1 的设备 | Proxmox 支持论坛 — Unable to get device for partition 1 on device /dev/mmcblk0 | Proxmox Support Forum

Hi,

Proxmox VE is not made for install on USB/eMMC/CFCard or equal. Proxmox VE have to be installed on a SSD/HDD. The OS will write some GB logs per day. A USB/eMMC/CFCard or equal will not last long with this many writing.

解决

不过也有绕过的办法,我们只要安装时选择Install Proxmox VE (Debug mode)，修改对应的perl安装脚本即可。

exit跳过第一个命令提示符，在第二次进入shell后，修改usr/share/perl5/Proxmox/Sys/Block.pm（可以使用vi或者nano）

切记选择/dev/mmcblk0也就是不带bootX后缀的盘符作为安装目标。

优化

当然官方说的还是有一定道理的，考虑到我也不想要这个emmc暴毙，我又做了一些优化来减少写入。

安装阶段

文件系统选择ext4

因为ZFS有严重的写放大和COW（写时复制）机制，对eMMC是毁灭性打击。

系统级优化

禁用swap

PVE 倾向于使用 Swap，频繁的内存交换会瞬间卡死 eMMC。

我们可以调低或者关闭它

1
2
3
4

7

# 关闭swap
swapoff -a

# 永久禁用：编辑 /etc/fstab，在 Swap 那一行开头加 # 注释掉。

# 如果内存很小必须使用swap，也可以考虑把 swappiness 调到最低
echo "vm.swappiness=0" >> /etc/sysctl.conf
sysctl -p

开启TRIM (垃圾回收)

eMMC 像 SSD 一样需要 TRIM 来保持性能。

1
2

systemctl enable fstrim.timer
systemctl start fstrim.timer

挂载参数优化 (noatime)

默认情况下，Linux 每次读取文件都会更新“访问时间”，这是无意义的写入。

操作：编辑 /etc/fstab，在根目录 / 的挂载选项中加入 noatime。

  • 修改前：defaults,errors=remount-ro
  • 修改后：defaults,noatime,errors=remount-ro

PVE 服务优化

禁用高可用 (HA) 服务

PVE 的 HA 服务会每隔几秒向磁盘写入心跳信息（Watchdog），单机环境下这毫无意义且伤盘。

1
2
3
4

systemctl stop pve-ha-lrm
systemctl stop pve-ha-crm
systemctl disable pve-ha-lrm
systemctl disable pve-ha-crm

# /etc/log2ram.conf 关键配置

SIZE=256M
默认通常是 40M，这对 PVE 来说太小了。
如果你内存有 8G 或以上，建议改为 256M 或 512M。
如果你内存只有 4G，建议改为 128M。

USE_RSYNC=true
确保设为 true。这会使用 rsync 增量同步，比 cp 更高效，减少写入。

ZL2R=true
开启后，它会使用 ZRAM 技术（内存压缩），这意味着你分配 256M 内存，实际能存大概 500M+ 的日志数据，且物理内存占用很小。这对 eMMC 小主机非常友好。

重启

df -h 看log2ram的size大小是否生效

log2ram的工作逻辑

  1. 开机时：把硬盘 /var/hdd.log (旧日志) 的内容加载到内存 /var/log。
  2. 运行时：PVE 所有的日志都写入内存，不读写 eMMC。
  3. 关机/重启时：自动把内存里的新日志同步回硬盘保存。
  4. 定时任务：它默认每天（daily）会自动同步一次到硬盘，防止断电导致全天日志丢失。
